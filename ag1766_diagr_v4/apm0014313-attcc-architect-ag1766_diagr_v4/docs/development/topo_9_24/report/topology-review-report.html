2. Executive Assessment

The current code contains a meaningful governed preview foundation: immutable v3 capture, typed projection, compatibility checks, reservation and leases, content-addressed artifacts, bounded recovery, and a stronger review service. However, the boundaries do not preserve one consistent semantic contract. Scope, category, endpoint identity and provenance are weakened between canonical facts, projection, profile and renderer. The actual application-specific two-page target is therefore not reproducible or certifiable from the current production profile set.

There is also a safety problem in the coexistence of legacy and governed paths. Upload and approval wiring can select legacy behavior while preview requires governed pins. Artifact delivery applies inconsistent verification by mode. Several relational and concurrency invariants remain service-only or non-atomic. These are activation blockers, not cosmetic backlog items.

The recommended approach is evolutionary governed vertical repair inside the existing FastAPI/Jinja/SQLAlchemy/Alembic/Draw.io modular monolith. Do not add a graph database, queue, event bus, microservice, or replacement web graph for this scope.

5. Root Causes

  1. Semantics are recreated differently at each boundary. Scope, category, identity and provenance are not one immutable typed contract.
  2. Legacy and governed paths coexist without one facade. Route wiring can bypass stronger services.
  3. The application-specific target is not an executable contract. The guide and target exist, but no reviewed production profile binds them.
  4. Relational integrity stops before the audit chain. Important cross-row and authority invariants are representable as invalid states.
  5. Concurrency concepts are split. CAS, ORM mutation, row versions, reparenting and recovery attempts do not use one transition protocol.
  6. UI truth is derived from rows rather than verified domain state. Metadata presence is treated as readiness.
  7. Completion evidence is not bound to current invariants. Historical plan statuses and HTML/Markdown copies drift from current source behavior.

Detailed causal chains and ownership order are in root_causes.md.

6. Proposed Target Architecture

Keep a modular monolith and relational persistence. Add a single TopologyApplicationFacade, immutable authority service, versioned scoped projector, approved profile registry, fenced generation protocol, page-qualified prototype renderer, atomic finalizer, bundle verifier/read model, governed review service, and bounded recovery service.

The central rule is: selection filters reviewed facts; it never supplies missing evidence. Missing scope, category or relationship semantics remain UNKNOWN or blocking. Projection version 1 remains readable for history but cannot be relabeled or approved as version 2.

State and data decisions

  • Separate semantic reservation attempt from worker recovery count.
  • Additive FK/CHECK/current-revision constraints follow data preflight and backfill; legacy rows remain readable.
  • Use page-qualified cell references and semantic IDs containing scope, category and relationship type.
  • Clone approved Draw.io prototypes and audit protected-region mutations.
  • Expose a verifier-derived state document to both HTTP and Jinja templates.
  • Keep scheduler, artifact deletion, graph database, event bus, microservice split and interactive viewer deferred.

Full component contracts, state machine, ER model, ADR proposals and rollout are in target.md.
