Context: question: dict with code, text, help, required_level, options answer: dict | None whose `value` is the stored response payload errors: dict | None The canonical CONTROLLED_SET payload is `{items: [{code, detail?, scope?}]}`, a list of objects rather than a list of codes, and the save route parses the submitted form field names through the response type. Each option therefore posts `items[].code`, which the route folds into one object per checked row; unchecked rows post nothing and are simply absent from the list. Read the payload with `.get('items')`, never `answer.value.items`: Jinja resolves attribute access before subscripting, so `.items` on a dict returns the built-in `dict.items` method instead of the stored list. #}
